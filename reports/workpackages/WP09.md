# WP09 handoff — conformance, differential, fuzz, and security evidence

## Scope completed

WP09 delivers the reproducible conformance and hostile-input evidence required
by `WP09-conformance-security.md`. The checkpoint is the `main` commit
containing this report, based on `884b6a9`. Two defects exposed while assembling
the gates were intentionally committed ahead of the WP09 evidence commit:

- `19000a1` retains the original language-tag spelling in direct parser source
  maps while lowercase remains structural/logical identity; and
- `b06d2e6` restores canonical iterator order when a nested composition rewrites
  anonymous document scopes, with direct, decoded, and mmap regressions.

The work package adds:

- a locally authored, redistribution-reviewed 17-artifact standards, errata,
  import-cycle, cross-syntax, and hostile-input corpus whose bytes, upstream
  Recommendation revisions, terms, transformations, and SHA-256 values are
  pinned by `tests/data/PROVENANCE.toml` and `corpus-lock.json`;
- an exhaustive generated ledger for all 76 registered model constructors,
  schema tags, productions, fields, canonical/reference/signature visitors,
  validators, required formats, Python/native differential paths, and wire;
- cross-syntax Python, forced-native Functional, native wire/index, independent
  wire-reader, and exact optional RDFLib 7.6.0 comparisons, with an empty
  fail-closed deviations registry and a Java oracle that is explicitly disabled
  in ordinary lanes;
- deterministic Hypothesis model, document/layout, import-graph, overlay,
  composition, language-identity, parser, and wire suites, plus bounded retained
  mutation families and a deterministic failure-class minimizer;
- native libFuzzer targets that compile the production Functional parser and
  wire decoder modules directly under their production limits/cancellation
  guards; and
- a 12-control security matrix covering XML/RDF hazards, diagnostic disclosure,
  path escape, SSRF/offline behavior, decompression, wire corruption, atomic
  cache publication, named resource limits, fuzzing, the native boundary, and
  supply-chain/Java audits, plus a coordinated-disclosure process draft.

The Python 3.10 TOML compatibility dependency is declared only in the
development extra; it is not a runtime dependency.

## Deviations and environment-only gates

There are no accepted product deviations, broad xfails, or WP09 skip markers.
`tests/data/deviations.toml` is intentionally empty; any future exception must
name its fixture, primary-standard ruling, comparator/version, owner, review
date, and removal gate.

The local host does not have a nightly toolchain or `cargo-fuzz`, so it did not
claim a timed ASan/UBSan libFuzzer campaign. Both target binaries compile against
the pinned lock and production modules, and ordinary Python/native mutation,
truncation, panic-boundary, cancellation, and resource gates pass. The
continuous sanitizer campaign described in `tests/fuzz/native/README.md` remains
an explicit release/CI environment gate; any finding must be minimized and
registered in the provenance ledger before release.

No mutable external corpus was downloaded. The retained corpus is deliberately
small, locally authored from cited primary standards, and hash-reproducible.
Large or upstream suites whose redistribution has not been reviewed remain
external manifests rather than silently copied fixtures.

The disclosure document is intentionally a draft: before a public 1.0 release,
WP12 must replace the repository-access private channel with a monitored contact
and obtain an accountable owner for the response targets. This is a publication
blocker, not a blocker for WP10/WP11 consuming the conformance contracts.

## Handoff

WP10 and WP11 may consume the committed corpus lock, constructor ledger,
deviations/errata decisions, security controls, deterministic generators, and
normal-lane commands without network access or Java. A new parser, writer,
constructor, wire tag, native feature, external oracle, retained failure, or
security-relevant I/O path must update the corresponding ledger/control and
regenerate the reports; a stale hash or ownerless deviation fails closed.

The normal acceptance commands are:

```console
pytest tests/conformance tests/security tests/fuzz
python -m tools.corpus.manifest --check
python -m tools.corpus.coverage --check
python -m tools.corpus.report --check
python -m tools.security.evidence --check
python tools/check.py --full
```

The RDFLib comparator and native sanitizer campaigns remain explicit
development/release lanes and are never imported, downloaded, or invoked by
package import, installation, or ordinary tests.
