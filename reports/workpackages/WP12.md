# WP12 handoff — packaging, supply chain, and release machinery

## Status

Complete for repository-owned implementation and local macOS/Python evidence.
The package is not release-ready: the multi-platform workflow has not yet
produced an approved candidate, and no local process can supply the external
name, URL, legal, publishing, signature, reference-machine, or owner approvals
listed below.

## Delivered

- `PYOWL_CORE_BUILD_NATIVE=0|1|auto` selects a complete universal pure wheel,
  a required native build, or an explicitly warned developer fallback. Official
  jobs never accept an accidental native fallback.
- PEP 517 metadata uses the PEP 639 Apache-2.0 expression and ships `LICENSE`,
  `NOTICE`, and the exact Cargo dependency/license inventory. The inventory is
  checked against `Cargo.lock` and deliberately records `legal_approval=false`.
- Deterministic supply-chain tooling emits a zero-runtime-component pure SBOM
  and a native SBOM containing the exact 14 locked crates.
- The archive inspector validates safe paths, duplicate names, modes, metadata,
  tags, license files, wheel `RECORD`, expected native-extension count, source
  completeness, and Java/JVM dependency or bootstrap indicators. The separate
  fail-closed platform auditor enforces architecture, dependency allowlists,
  RPATH/install-name/deployment-target policy, Python exports, stable native
  build paths, and checksum-bound coverage of all 25 native wheels.
- The import probe fails on network/process/file-write side effects, eager
  extension loading, warnings, or forbidden integration imports.
- The release-report generator binds every file to SHA-256, enforces the
  pure/sdist/native set shape, and treats every absent or non-passing internal
  and external gate as a blocker.
- `wheels.yml` defines one pure wheel, one sdist, and 25 version-specific native
  wheels across CPython 3.10–3.14 on Linux x86_64/aarch64, macOS x86_64/arm64,
  and Windows x86_64. It requires byte-identical sdist, pure-wheel, and native
  rebuilds; runs the complete tests against every installed native wheel; and
  retains RustSec, five platform manifests, and a 29-target resolver matrix.
  Rust is pinned to the crate MSRV, 1.83.0.
- `release.yml` consumes an explicit successful Wheels run rather than
  rebuilding, verifies the exact signed tag/source and every signed subject,
  and separates protected TestPyPI and PyPI Trusted Publishing environments.
  Both indexes are re-fetched and all 27 file digests and PEP 740 identities
  are cryptographically checked before the workflow can finish.
- The release/yank/security procedure preserves immutable files and reflects
  PyPI's release-level yank behavior.

## Local evidence

- Python 3.12: `485 passed, 3110 subtests passed`.
- Python 3.10 pure lane: `418 passed, 66 native-only skips, 402 subtests passed`.
- Focused packaging/docs/release/audit suites: `77 passed` on both Python 3.10
  and 3.12.
- Two fixed-epoch sdists were byte-identical, and the pure wheel built directly
  was byte-identical to the wheel rebuilt from the sdist. The artifacts passed
  structural inspection.
- The pure wheel installed from a local directory on Python 3.10 without
  dependencies; its import probe and both executable documentation examples
  passed outside the checkout.
- A forced CPython 3.10 macOS x86_64 wheel installed outside the checkout,
  passed the native examples and extension self-test, and rebuilt to identical
  bytes. It exports only `PyInit__native`, links only system
  `libiconv`/`libSystem`, targets macOS 13.0, has the expected
  `@rpath/_native...so` install name and zero `LC_ID_DYLIB` timestamp, and
  contains no nondeterministic `LC_UUID` command and uses stable remapped Rust
  paths rather than checkout/Cargo paths. Clean builds with different Cargo
  target directories produced byte-identical wheels.
- Ruff, strict mypy for the packaging helpers, dependency/SBOM regeneration,
  repository audits, and `git diff --check` pass.
- A post-implementation read-back against the WP12 and packaging specs found
  no remaining repository-owned packaging gap; the hosted and owner-controlled
  gates below remain deliberately unresolved.

The checked evidence under `reports/release/0.1.0.dev0/` is engineering
evidence. A final workflow artifact/report must bind the complete platform set
to the selected signed source revision.

## Remaining release blockers

- The hosted 27-distribution matrix, platform binary audits, local-index target
  resolver matrix, maintained advisory scan, and attestation flow must succeed
  from the selected signed tag.
- An accountable owner must confirm PyPI and TestPyPI control of the provisional
  `pyowl-core` name and approve real repository, documentation, and issue URLs.
- Legal review must approve the recorded third-party choices and obligations.
- Trusted Publisher/recovery identities, TestPyPI rehearsal, signatures/index
  attestations, and release-owner approval do not yet exist.
- The approved reference-machine performance gates and a refreshed exact
  consumer matrix remain blocked outside this work package's local evidence.

No approved deviation waives any item above. Missing evidence is a blocker, not
a pass, and no package publication or name reservation was attempted.
