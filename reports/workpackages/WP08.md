# WP08 handoff — native Functional parser and axiom-type index

## Status

Complete for the capabilities advertised by this work package. The native
feature ledger now adds exactly:

- `parse-functional-v1`
- `index-axiom-types-v1`

OWL/XML, Turtle, RDF/XML/RDF mapping, and native snapshot construction are not
advertised. `AUTO` chooses the complete Python implementation for those
operations before parser/index work, while forced `NATIVE` fails with a typed
capability error. There is no mid-operation or partial fallback.

Dependencies WP02, WP05, and WP07 were present at baseline commit
`8baa1ea3b5a8db7ff5bff2308eca92c75b6065a4`.

## Delivered behavior

### Functional-Style parsing

- Safe-Rust UTF-8/BOM lexer with comments, strings, IRI escapes, language tags,
  prefixes, exact byte/line/column starts, checked nesting, and cooperative
  work/cancellation checkpoints.
- Complete permanent model-constructor coverage, including optional
  cardinality fillers, ordered property/data-property sequences, canonical
  unordered operands, annotations, anonymous individuals, and opt-in SWRL.
- Schema-1 canonical builders whose rows are validated by the independent WP07
  native canonical scanner before publication.
- Provisional anonymous keys exactly match the Python parser. The established
  shared document-freeze path performs final document-scoped anonymous
  canonicalization, so public fingerprints and source/origin maps are equal.
- One owned coarse request and one owned coarse result; Rust work runs detached
  from the GIL. No public Rust or Horned-OWL value crosses the boundary.
- Native syntax, unsupported-extension, cancellation, deadline, and resource
  failures map to the existing public exception taxonomy.

### Axiom-type index

- One coarse canonical-row request is scanned natively under aggregate term,
  row, byte, memory, work, deadline, and cancellation budgets.
- The deterministic result partitions original canonical ordinals by schema
  tag. Python validates every tag/ordinal and publishes the existing immutable
  `AxiomTypeIndex` representation.
- Full snapshot builds can use the native operation. Overlay and composite
  indexes retain their existing patched/merged adapters and reuse native-built
  parent postings without copying bases.
- Build reports, row counts, table-byte accounting, exact-constructor queries,
  categories, canonical iteration, origins, overlays, and composites remain
  byte/value-equivalent to Python.

### Dispatch and compatibility

- Explicit `PYTHON` remains silent and does not import native modules.
- Forced `NATIVE` never falls back.
- `AUTO` uses measured conservative cutovers before work: Functional sources
  below 256 KiB and axiom-type closure indexes below 4,096 rows stay Python.
  Non-closure scoped AUTO index builds also stay Python because the closure
  report is not an exact scoped-size predictor.
- The private PyO3 stub now reflects optional typed cancellation for parser and
  index calls. ABI, model schema, and wire versions remain unchanged.

## Performance evidence

Informative local measurements were taken on Darwin 25.5 x86_64, CPython
3.12.3, Rust 1.83.0, release mode. Inputs and outputs were checked for semantic
parity before timing. Values are medians; acquisition is excluded because the
inputs were resident bytes, while public parse includes model materialization,
anonymous freeze, provenance, fingerprints, source/origin construction as
configured by the default public call.

| operation | workload | Python | native | native/Python |
|---|---:|---:|---:|---:|
| raw Functional parse | 100 axioms / 3,599 B / 20 runs | 6.080 ms | 6.396 ms | 1.052 |
| public Functional parse | 100 axioms / 3,599 B / 20 runs | 11.462 ms | 11.731 ms | 1.023 |
| raw Functional parse | 8,000 axioms / 302,899 B / 5 runs | 554.364 ms | 509.127 ms | 0.918 |
| public Functional parse | 8,000 axioms / 302,899 B / 5 runs | 1.0649 s | 1.0023 s | 0.941 |
| public axiom-type build | 100 rows / 20 runs | 2.958 ms | 1.791 ms | 0.606 |
| public axiom-type build | 4,100 rows / 7 runs | 140.313 ms | 69.177 ms | 0.493 |
| public axiom-type build | 10,000 rows / 5 runs | 320.217 ms | 170.588 ms | 0.533 |

The parser does not meet a 2x end-to-end throughput claim on this synthetic
constructor-heavy corpus; no such claim is made. Its measured benefits are GIL
release, bounded native lexical/structural validation, and a modest large-input
gain. The axiom-type index removes the duplicate Python canonical-key pass and
is about 2x faster at the AUTO cutover. The conservative thresholds prevent
small-input regressions in AUTO; forced NATIVE remains available for explicit
testing and deployment policy.

## Security and ownership

- `#![forbid(unsafe_code)]` remains active; no unsafe block, Java dependency,
  network bootstrap, new crate, or license obligation was introduced.
- Input lengths/counts are checked before address conversion/allocation; native
  output sizes are precomputed and checked before reservation/publication.
- Results are built privately and published only after canonical/category,
  framing, limit, cancellation, and final-boundary validation succeeds.
- Changes stay in WP08 native/parser/index/session/source/canonical and test
  paths plus the authorized minimal integration files: native module boundary,
  private stub, native adapter, backend dispatch, Python parser entry,
  axiom-type entry, and one stale capability-dependent unit assertion.

## Deliberate non-capabilities / next work

- OWL/XML and RDF-family native parsing/mapping remain Python-only and absent
  from `FEATURES`; `native/src/map_rdf.rs` is intentionally not a placeholder.
- Final anonymous graph canonicalization and whole-document freeze remain in
  the shared Python semantic layer after the complete native Functional parse.
- Native snapshot construction, native writers, mmap startup, and bounded
  parallel parsing remain separate capabilities and are not implied here.
- Biomedical pinned-corpus/reference-machine baselines remain WP10 work. The
  synthetic timings above justify dispatch policy but are not publication
  throughput claims.
