## Post-WP05 stream-acquisition integration addendum

A pyELK WP2 integration review found that the public `DocumentInput` alias
admitted caller-owned binary/text streams while `load_snapshot` and
`coerce_snapshot` had no way to supply the document IRI already required by
the one-document acquisition layer. The narrow repair adds a keyword-only
`document_iri: IRI | str | None` to both facades and to `SnapshotLoader.load`.
It is deliberately not a `LoadOptions` field: it identifies only the unparsed
root, while each imported document remains bound by its resolver result.

The follow-up contract proves:

- binary and text streams pass their base into root parsing, are acquired in
  one forward pass, remain caller-owned, and are not retried after syntax
  failure;
- missing stream metadata and invalid argument types fail before the first
  read; text streams still require `LoadOptions.format`;
- path sources still derive an absolute `file:` document IRI and bytes still
  retain no document IRI when the keyword is omitted;
- an explicit root IRI may override the parser base for an unparsed path or
  bytes source without changing its acquisition locator; and
- parsed documents, existing views, and providers reject the acquisition-only
  keyword with `DOCUMENT_IRI_SOURCE_CONFLICT`, so no existing value is rebased,
  copied, reparsed, or provider-invoked.

On CPython 3.10.11 and 3.12.3 the complete post-fix suite passes 209 tests and
402 generated subtests. Repository audits, Ruff, strict mypy, sdist and
wheel builds, and clean installed-wheel stream smoke tests pass on both
runtimes. No Java/native artifact, runtime dependency, retry path, WP06 wire
surface, or consumer-private state was added.

The exact standalone consumer handoff is:

```python
view = pyowl_core.coerce_snapshot(
    source,
    document_iri="urn:pyelk:input",  # required for BinaryIO/TextIO
    options=pyowl_core.LoadOptions(
        format=pyowl_core.DocumentFormat.FUNCTIONAL,  # required only for TextIO
        imports=pyowl_core.ImportPolicy.IGNORE,
    ),
)
```

Paths and bytes keep their existing calls and behavior. Already-loaded
`OntologyView`/`SnapshotProvider` inputs omit `document_iri` and preserve exact
identity.
