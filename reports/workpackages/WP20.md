# WP20 — strict RDF mapping evidence

Status: source-backend acceptance complete; final native-artifact rerun pending
Prepared: 2026-08-02

## Outcome

Strict RDF/XML and Turtle mapping failures now carry an immutable
`RDFMappingReport` on `UnsupportedSyntaxError.rdf_mapping_report`. The report
is constructed from the mapping ledger before `RDF_MAPPING_INCOMPLETE` is
raised, so a consumer can inspect exact total, consumed, and dropped statement
counts plus bounded deterministic examples without reparsing the document.

Each `RDFTripleEvidence` records `object_kind` using the frozen `iri`, `blank`,
or `literal` vocabulary. Subject, predicate, and object representations are
printable, UTF-8 bounded, and have URI userinfo redacted. The native retained
facade normalizes the same contract and detaches the report from failed native
storage before cleanup.

The native mapping closeout makes one complete pass over the consumed ledger.
It counts every unconsumed triple while retaining only the first
`max_diagnostics` examples in Python contractual order. Public strict
publication raises from that retained report; diagnostic partial publication
uses the same first-pass report.

## Contract checkpoint

- strict rejection remains the default;
- `0 <= consumed_triples <= total_triples` is validated, and `conformant`
  must agree with those counts;
- `dropped_triples` is the exact `total_triples - consumed_triples` value;
- reports are valid only on `RDF_MAPPING_INCOMPLETE` errors; and
- forced Python/native RDF/XML and Turtle fixtures compare complete public
  reports and assert one parser entrypoint invocation.
