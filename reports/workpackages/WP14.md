## Decisions frozen for implementation

- Public documents/snapshots own opaque private handles; a handle owns its
  immutable arena or retains the immutable validated mapping owner.
- Dependent scalar values, indexes, overlays/composites, and encoded views keep
  the required owner alive; no unowned pointer crosses calls.
- Native load/freeze creates only O(documents + diagnostics + fixed facade
  metadata) Python objects before scalar access. Scalar values are lazy and
  caches cannot permanently duplicate the ontology.
- `EncodedStructuralView` is requested through the public `OntologyView.view`
  boundary, uses core-owned read-only little-endian buffers and canonical
  descriptor metadata, and retains its exact originating view as owner.
- WP17, not WP14/WP15, freezes schema 1 and any API/adapter version change.
  Until then the encoded schema is not advertised.
- PYOCORE remains the sole stable cross-process format. mmap publication owns
  one validated immutable mapping and performs neither row-wise Python
  materialization nor a complete native copy.
- Consumers negotiate `CoreCapabilities`, especially
  `retained-native-load-v1`, `ontology-identity-index`, `wire-v1`,
  `wire-verified`, and
  `encoded_view_schemas["pyowl-core/structural-columns"]`. Package version
  strings and private extension imports are not negotiation mechanisms.
- Capability selection happens before input consumption. Unsupported `AUTO`
  operations use the complete Python path; forced `NATIVE` fails explicitly.

## Timing decision

Resident-byte timers include parsing/mapping, interning, canonicalization,
freeze, required indexes, four fingerprint preimages/digests, identity,
diagnostics/provenance, publication, and complete common-ledger traversal.
Only comparison of already-produced ledger bytes/counts/digests and bounded
sample validation occur after the timer. Acquisition/network/resolver I/O is
separate.

For the core Python lane, retained-handle/facade publication is `n/a`; the
ordinary Python snapshot and common-contract ledger still finish inside the
timer. The current scaffold implements only resident-byte fresh/steady smoke,
not file acquisition or paired randomized execution.

Raw `horned-model-ready` remains asymmetric diagnostic evidence. Only Horned
engine time plus the complete independent `common-contract-ready` adapter may
be used as the Horned-equivalence denominator. Direct Rust and installed-wheel
lanes, resident-byte and file lanes, and fresh- and steady-process modes are
reported separately.

## Acceptance state

WP14 acceptance is open. There is no approved reference-machine evidence for
the redesign counters or comparator gates. All external runner pins remain
pending and non-runnable; persistent external runners, file execution, paired
randomization, executable ratio gates, and representative matrix evidence are
not implemented. The limited source/sdist/pure-wheel exclusion audit passed,
but native-wheel linkage, SBOM/license, and release-packaging evidence are
still incomplete. Therefore:

- no `<= 1.10` Horned equivalence result exists;
- no OWLAPI or fastest-implementation result exists;
- no retained object/copy/RSS or mmap-startup gate has passed;
- no threshold amendment is proposed; and
- `retained-native-load-v1` and the encoded structural schema remain
  unadvertised.

## Handoff

WP15 may proceed with the opaque handle, immutable arena, lazy facade,
lifetime, allocation-counter, generated/wire-input adapter, and fail-closed
binding seams recorded in the decision. WP15 must preserve the full Python
backend and cannot close WP14's comparative evidence by implementation alone.

WP14 closes only after every external runner pin and artifact is complete,
audited persistent runner processes execute the equivalent contracts, the
installed native wheel runs in isolation, and approved reference-machine
fresh/steady and resident/file samples cover the representative matrix. Paired
randomized profiles, passing executable ratio gates, current object/copy
counters, native-wheel linkage, SBOM/license evidence, and approved release
packaging must also be committed and reviewed. Until then documentation must
describe the native backend as experimental acceleration and must not claim
Horned/OWLAPI parity or multi-consumer zero-materialization performance.
