# WP16 — native streaming parsing and structural mapping

Status: implementation checkpoint; guarded Functional loads keep structural
publication bytes native and the private RDF/XML retained slice is expanding,
complete multi-format/closure acceptance open
Prepared: 2026-07-21
Capability claim: none

## Outcome

WP16 now has a fail-closed retained-owner handoff for a deliberately guarded
Functional Syntax shape: one document, native parsing selected explicitly or
by the existing AUTO size/capability policy, OWL 2 DL validation disabled, and
no RDF mapping report. Source maps may be retained. Imports may be ignored,
recorded unresolved when no resolver can produce a closure member, or use
either resolver-backed policy when the native parser proves the direct-import
set is empty before publication. An actual resolver-backed import selects
complete framing before publication. Provenance may be enabled or disabled;
the latter publishes no origin capability or table.
The Functional parser constructs the typed V2 arena directly from its own
canonical nodes in the same detached native call. For eligible loads, Python
receives only compact ontology/import metadata and fixed-size prepared digest
evidence. Canonical root temporaries, structural/logical/signature fingerprint
preimages, and origin-row encoding remain native; no ontology-sized canonical
byte collection or provenance occurrence object is copied into Python. Native
preparation streams one temporary row at a time from the retained arena,
enforces cancellation and temporary/owner memory limits, and finalization
rechecks all six content digests plus cardinality and capability claims.
Duplicate roots remain deduplicated without losing origin occurrences. The
encoded structural view and PYOCORE writer consume retained columns without
scalar model traversal.

This is a checkpoint, not WP16 acceptance. The native call still returns the
complete parser-result framing for explicit fallback cases, including
RECORD_UNRESOLVED loads whose diagnostic metadata would exceed the retained
publication bound and resolver-backed imports requiring a closure. The guarded
public-load promotion proof is still Functional-only; resolver-backed import
closure, Turtle, and OWL/XML remain outside the path. The bridge is
intentionally absent from the ingestion capability ledger, and the encoded
view schema is likewise unadvertised.

The separate private RDF/XML production seam now also accepts the standard
`rdf:parseType="Resource"` property form. It emits the implicit blank node and
nested property edges during the forward XML scan, maps structural class
expressions exactly, and publishes the result through the typed retained V2
owner without crossing the Python RDF/XML parser or copying structural rows at
publication. Property-element statement reification now reaches complete graph
construction, while the strict OWL mapper remains fail-closed for its classic
metadata. This additional syntax coverage does not advertise `parse-rdfxml-v1`
or make RDF/XML a public routing target.

Node-element property attributes now follow the same bounded forward path.
`rdf:type` attribute values resolve against the active XML base, ordinary
property attributes become exact language or `xsd:string` literals, and
`xml:lang=""` correctly clears an inherited language. Reserved RDF/XML syntax
terms remain rejected rather than being misinterpreted as predicates.

Empty property elements can now describe their selected object in the same
scan. `rdf:resource`, `rdf:nodeID`, and implicit blank objects receive exact
attribute-form type and literal edges before the outer property edge is
published. IRI/base and language semantics match node property attributes;
literal and triple limits remain live. Statement reification shares the graph
path described below.

The legacy datatype-plus-property-attribute form now follows the established
Python/RDFLib compatibility contract: `rdf:datatype` selects an empty typed
literal and additional property attributes are ignored instead of constructing
an implicit blank object. The native graph therefore emits only the typed
literal edge. A fully mappable ontology-annotation fixture reaches the private
retained V2 owner with exact canonical, fingerprint, report, wire, and
zero-structural-copy parity.

Container membership properties now expand `rdf:li` to node-local `rdf:_1`,
`rdf:_2`, and subsequent predicates in document order, including inside
implicit `parseType="Resource"` nodes. Expanded element IRIs and generated
membership IRIs are bounded, counter overflow fails before graph publication,
and reserved core/withdrawn RDF names are rejected in invalid node, property,
attribute, and root roles.

`rdf:parseType="Literal"` properties now stream complete XML fragments into
exact `rdf:XMLLiteral` terms. The retained lexical form matches Python's
ElementTree serialization for namespace declarations, attributes, nested and
empty elements, mixed text, and child tails; decoded entities and CDATA remain
in document order. Inherited language is suppressed, literal limits stay live
during serialization, and XInclude is still forbidden. XML-literal statement
reification now reaches complete graph construction. Every other `parseType`
value follows the same XML-literal production.

The forward XML scanner now accepts the complete XML 1.0 Unicode name ranges
for element, attribute, and namespace-prefix names. Qualified names still have
strict namespace structure: multiple colons and malformed namespace
declarations fail before graph publication, as does an empty property-element
`rdf:nodeID`. Unicode annotation names cross the same retained owner with exact
Python mapping and wire parity.

XML 1.0 value normalization now also happens in the forward scan. Literal text
and CDATA normalize raw CR and CRLF endings to LF, attribute values normalize
raw XML whitespace to spaces, and numeric character references retain their
referenced characters. The same event stream feeds nested XMLLiteral
serialization, including ElementTree-compatible escaped attribute whitespace.
Forbidden raw XML characters and a literal `]]>` in character data fail before
graph or owner publication.

The XML envelope is now validated before RDF parsing. XML declarations require
the ordered `version`, optional `encoding`, and optional `standalone`
pseudo-attributes; the declaration must agree with the detected UTF-8,
UTF-16LE, or UTF-16BE source. UTF-16 byte-order marks and XML byte signatures
select a bounded two-pass decoder that rejects odd code units and invalid
surrogates before allocation, preserves decoded-codepoint accounting, and
continues to reject UTF-32. Reserved `xml`/`xmlns` namespace bindings and
prefixed namespace undeclarations follow the namespace constraints, while an
explicit correct `xml` binding and default-namespace undeclaration remain
valid. The positive envelope crosses retained publication; malformed forms
publish no graph or owner. Declaration versions are restricted to XML 1.0,
and comments reject both embedded double hyphens and a trailing hyphen before
the closing marker.

Ordinary XML processing instructions now follow the RDF/XML Infoset mapping:
their targets and content are lexically validated, then they produce no RDF
events. Instructions before, inside, and after the document element are
accepted, including an inert `xml-stylesheet` target, without invoking a target
handler or external resource. Case-insensitive reserved `xml` targets,
malformed target boundaries, and misplaced XML declarations still fail before
graph publication. Differential and retained-owner fixtures preserve exact
Python mapping and wire parity.

Property-element `rdf:ID` now emits the original statement plus the complete
four-triple RDF 1.1 reification for literal, resource, nested-node,
`parseType="Resource"`, empty and nonempty collection, and XML-literal forms.
The reification IRI follows the active XML base. `rdf:ID` and `rdf:nodeID`
values enforce the XML NCName grammar, including Unicode names, and the
document-wide (`rdf:ID` value, base) uniqueness constraint spans node and
property elements. The ID ledger, object copies, and duplicate checks remain
under native memory/work limits, while every emitted statement remains under
`max_triples`. Classic `rdf:Statement` metadata is still unconsumed by the
strict OWL reverse mapper, so a reified graph fails before retained-owner
publication and makes no capability claim.

RDF/XML 1.1 `parseTypeOther` values now behave exactly like
`rdf:parseType="Literal"` in both the Python reference parser and native forward
scanner. Arbitrary values, nested markup, mixed tails, suppressed inherited
language, XML-literal limits, and optional `rdf:ID` reification reuse the same
bounded event/serialization path without emitting value-specific triples. A
fully mappable annotation fixture crosses the private retained V2 owner with
exact Python canonical, fingerprint, report, wire, and zero-structural-copy
parity.

The private single-document RDF/XML seam now owns anonymous-individual
canonicalization as well. Provisional parser labels are alpha-canonicalized in
Rust against the complete mapped document, assigned exact raw document scopes,
then re-scoped into the ordinal-zero snapshot scope before the typed V2 owner is
frozen. Raw and effective root tables remain distinct, provenance keeps both
origin tables, and Python receives neither structural rows nor a model to
re-scope. Symmetric blank graphs remain bounded by the shared canonical-work
limit. Its parsed trees, labels, paths, graph candidates, and raw/effective
encodings use fallible reservations charged before allocation to both the
temporary-workspace ceiling and the operation-wide live-memory budget. This
does not cover multi-document import scoping or advertise RDF/XML.

The guarded single-document Functional seam now uses that same native scoping
engine instead of exporting complete parser framing for Python re-scoping.
Parser-order raw/effective digest pairs keep duplicate lexical occurrences,
source spans, source maps, and provenance exact even when the canonical root
tables sort and deduplicate the corresponding values. The typed owner retains
distinct raw and effective root/origin tables, while document, structural,
logical, signature, and wire evidence match the Python reference without
invoking the complete Functional model decoder. Scoping allocations remain
under the shared temporary-workspace and live-memory budgets.

## Acceptance state

WP16 acceptance remains open. In particular:

- the guarded Functional path now constructs and publishes its retained arena
  without eagerly decoding a complete Python structural model or copying
  proportional canonical/preimage/origin data into Python; single-document
  anonymous-node re-scoping is also native, while diagnostic-budget and
  resolver-backed closure fallbacks still use complete-model decode;
- RDF/XML, Turtle, and OWL/XML are not complete native ingestion paths, and the
  full Functional format/option/import matrix has not passed retained
  publication despite AUTO, all-policy empty-closure, ignored-import, and
  no-resolver unresolved-import coverage;
- native closure assembly does not yet prove shared-import digest parsing,
  diamonds/cycles, anonymous scopes, partial failure, cancellation, or
  deterministic bounded parallel publication;
- complete diagnostics/source-position, writer, W3C/corpus, hostile, fuzz,
  memory/object, and phase-allocation evidence is absent; and
- no ingestion format or encoded schema may be advertised from this checkpoint.

WP16 can close only after each advertised format completes the installed-wheel
forced-native matrix, unsupported selections fail before consumption, fallback
detection remains active, and parser-to-arena plus retained-closure evidence
demonstrates that no RDFLib graph, proportional Python triple/axiom collection,
or eager complete Python model conversion occurs.
