# WP16 — native streaming parsing and structural mapping

Status: implementation checkpoint; guarded Functional loads keep structural
publication bytes native and the private RDF/XML retained slice is expanding,
complete multi-format/closure acceptance open
Prepared: 2026-07-24
Capability claim: none

## Outcome

WP16 now has a fail-closed retained-owner handoff for a deliberately guarded
Functional Syntax shape: one document, native parsing selected explicitly or
by the existing AUTO size/capability policy, OWL 2 DL validation disabled, and
no RDF mapping report. Source maps may be retained. Imports may be ignored,
recorded unresolved when no resolver can produce a closure member, or use
either resolver-backed policy when the native parser proves the direct-import
set is empty before publication. An actual resolver-backed import selects
complete framing before publication. Provenance may be enabled or disabled;
the latter publishes no origin capability or table.
The Functional parser constructs the typed V2 arena directly from its own
canonical nodes in the same detached native call. For eligible loads, Python
receives only compact ontology/import metadata and fixed-size prepared digest
evidence. Canonical root temporaries, structural/logical/signature fingerprint
preimages, and origin-row encoding remain native; no ontology-sized canonical
byte collection or provenance occurrence object is copied into Python. Native
preparation streams one temporary row at a time from the retained arena,
enforces cancellation and temporary/owner memory limits, and finalization
rechecks all six content digests plus cardinality and capability claims.
Duplicate roots remain deduplicated without losing origin occurrences. The
encoded structural view and PYOCORE writer consume retained columns without
scalar model traversal.

The RDF/XML evidence now locks the complete 317-file upstream W3C RDF/XML
subtree byte-for-byte and executes all 166 active manifest entries: 126
positive graph-result cases and 40 negative syntax cases. Python and the
test-hook native graph seam have exact positive/negative outcome parity, with
every positive graph isomorphic to the locked expected result. The graph seam
is compiled and registered only under `test-hooks`; production builds omit it
and `INGESTION_FEATURES` remains empty. This is locked-corpus parity evidence,
not W3C endorsement or conformance certification.

This is a checkpoint, not WP16 acceptance. The native call still returns the
complete parser-result framing for explicit fallback cases, including
RECORD_UNRESOLVED loads whose diagnostic metadata would exceed the retained
publication bound. Forced-native Functional closures in either provenance mode
can now retain their final multi-document snapshot in one native owner. The
provenance path retains per-document raw and effective origin tables plus one
canonical closure table while sharing row payloads. Python still performs
resolution, owns the complete document models, and serializes proportional
canonical root and origin tuples for that boundary. The guarded public-load
promotion proof remains Functional-only; end-to-end native closure assembly,
Turtle, and OWL/XML remain outside the path. The bridge is intentionally absent
from the ingestion capability ledger, and the encoded view schema is likewise
unadvertised.

The separate private RDF/XML production seam now also accepts the standard
`rdf:parseType="Resource"` property form. It emits the implicit blank node and
nested property edges during the forward XML scan, maps structural class
expressions exactly, and publishes the result through the typed retained V2
owner without crossing the Python RDF/XML parser or copying structural rows at
publication. Property-element statement reification now reaches complete graph
construction, while the strict OWL mapper remains fail-closed for its classic
metadata. This additional syntax coverage does not advertise `parse-rdfxml-v1`
or make RDF/XML a public routing target.

Node-element property attributes now follow the same bounded forward path.
`rdf:type` attribute values resolve against the active XML base, ordinary
property attributes become exact language or `xsd:string` literals, and
`xml:lang=""` correctly clears an inherited language. Reserved RDF/XML syntax
terms remain rejected rather than being misinterpreted as predicates.

Empty property elements can now describe their selected object in the same
scan. `rdf:resource`, `rdf:nodeID`, and implicit blank objects receive exact
attribute-form type and literal edges before the outer property edge is
published. IRI/base and language semantics match node property attributes;
literal and triple limits remain live. Statement reification shares the graph
path described below.

The legacy datatype-plus-property-attribute form now follows the established
Python/RDFLib compatibility contract: `rdf:datatype` selects an empty typed
literal and additional property attributes are ignored instead of constructing
an implicit blank object. The native graph therefore emits only the typed
literal edge. A fully mappable ontology-annotation fixture reaches the private
retained V2 owner with exact canonical, fingerprint, report, wire, and
zero-structural-copy parity.

Container membership properties now expand `rdf:li` to node-local `rdf:_1`,
`rdf:_2`, and subsequent predicates in document order, including inside
implicit `parseType="Resource"` nodes. Expanded element IRIs and generated
membership IRIs are bounded, counter overflow fails before graph publication,
and reserved core/withdrawn RDF names are rejected in invalid node, property,
attribute, and root roles.

RDF collection decoding now applies `max_sequence_arity` to the raw list cells
in both the Python reference mapper and native decoder, alongside the dedicated
`max_rdf_list_length` budget. Repeated members therefore cannot evade the raw
sequence bound by collapsing in a later canonical set.

Typed OWL 1 class-expression list forms now have the same compatibility
semantics in the Python reference mapper and native decoder. Empty
intersections become `owl:Thing`, empty unions and object enumerations become
`owl:Nothing`, and singleton intersections/unions become their sole operand;
the same shapes without an `owl:Class` marker remain unsupported rather than
leaking a structural-model exception.

OWL 1 constructor triples attached directly to a declared named class now map
to `EquivalentClasses` in both backends. Named complements, empty and singleton
booleans, and empty or populated enumerations share the same canonical folding;
the OWL 1 named-enumeration form rejects anonymous members consistently.

Legacy `rdfs:Class`, `rdf:Property`, and restriction `owl:Class` type markers
are now consumed by the Python reference mapper only when another recognized
OWL type makes them redundant, matching native behavior; standalone markers
remain structurally incomplete. Inferred `owl:SymmetricProperty` declarations
now consume a colocated legacy `rdf:Property` marker just like inverse-
functional and transitive properties; the same marker on a nonproperty remains
incomplete. An empty `owl:DataRange` enumeration maps to the complement of
`rdfs:Literal`, while the corresponding modern datatype form and invalid
compatibility-marker combinations fail explicitly.

Detached blank-node `owl:inverseOf` object-property expressions now complete
reverse mapping when their unique named target is already established as an
object property. The structural triple is consumed without inventing an axiom;
named-subject inverse-property triples still map to their ordinary axiom.
Undeclared or anonymous targets remain incomplete, duplicate targets fail with
the cardinality category in both backends, and the private retained owner makes
no RDF/XML capability claim.

Detached typed blank-node `owl:complementOf` class expressions now complete
reverse mapping when their unique named target is already established as a
class. The `owl:Class` marker and complement edge are consumed without
inventing an axiom; named-subject OWL 1 constructor triples still map to
`EquivalentClasses`. Markerless, undeclared, anonymous, and cyclic forms remain
incomplete, duplicate targets fail with the cardinality category in both
backends, and the private retained owner makes no RDF/XML capability claim.

Detached typed blank-node `owl:datatypeComplementOf` data ranges now complete
reverse mapping when their unique named target is already established as a

inventing an axiom. Markerless, named-subject, undeclared, anonymous, and
cyclic forms remain incomplete, duplicate targets fail with the cardinality
category in both backends, and the private retained owner makes no RDF/XML
capability claim.

Detached typed blank-node `owl:oneOf` data enumerations now complete reverse
mapping when they carry an unclaimed standard `rdfs:Datatype` marker and a
nonempty RDF list containing only literals. The marker, constructor edge, and
list cells are consumed without inventing an axiom. Markerless, named-subject,
and OWL 1 marker-only forms remain incomplete; empty, nonliteral, and
conflicting-marker forms remain unsupported; duplicate constructor targets
fail with the cardinality category in both backends; and the private retained
owner makes no RDF/XML capability claim.

Detached OWL 1 `owl:DataRange` enumerations now complete reverse mapping for
both nonempty literal lists and the empty-list compatibility form. The latter
decodes to the complement of `rdfs:Literal`; both forms consume the marker,
constructor edge, and list structure without inventing an axiom. Markerless
and named-subject forms remain incomplete, conflicting markers, nonliteral
items, and other constructors remain unsupported, duplicate targets fail with
the cardinality category in both backends, and the private retained owner makes
no RDF/XML capability claim.

Detached typed blank-node `owl:oneOf` object enumerations now complete reverse
mapping for a nonempty named-individual list and the empty-list compatibility
form. The latter decodes to `owl:Nothing`; both forms consume the `owl:Class`
marker, constructor edge, and list structure without inventing an axiom. Named
subjects preserve the existing OWL 1 `EquivalentClasses` mapping, markerless
forms remain incomplete, literal items and conflicting constructors remain
unsupported, duplicate targets fail with the cardinality category in both
backends, and the private retained owner makes no RDF/XML capability claim.

Detached typed blank-node empty class booleans now complete the OWL 1
compatibility forms for both `owl:intersectionOf rdf:nil` and
`owl:unionOf rdf:nil`. They decode internally to `owl:Thing` and `owl:Nothing`
respectively, consume the `owl:Class` marker and constructor edge, and invent
no axiom. Named subjects preserve their existing OWL 1 equivalence mapping;
markerless and restriction-conflict forms remain incomplete; mixed
constructors remain unsupported; duplicate selected edges fail with the
cardinality category only after the class marker is established; and the
private retained owner makes no RDF/XML capability claim.

Detached typed blank-node nonempty class booleans now also complete reverse
mapping when every member of the exact RDF list is a named class already
established by a declaration. Singleton intersections and unions fold to their
sole operand, while lists of two or more members decode through the standard
boolean constructors; the detached expression itself emits no axiom. The
eligibility pass is non-mutating, cycle-aware, cancellation/work charged, and
bounded by both RDF-list and sequence limits plus native temporary memory.
Named subjects preserve the existing OWL 1 equivalence mapping. Markerless,
undeclared, anonymous-member, forked, cyclic, and class-plus-restriction forms
remain incomplete; conflicting constructors and shared collection tails
remain unsupported; duplicate eligible constructor edges retain the
cardinality category; and the private retained owner makes no RDF/XML
capability claim.

`rdf:parseType="Literal"` properties now stream complete XML fragments into
exact `rdf:XMLLiteral` terms. The retained lexical form matches Python's
ElementTree serialization for namespace declarations, attributes, nested and
empty elements, mixed text, and child tails; decoded entities and CDATA remain
in document order. Inherited language is suppressed, literal limits stay live
during serialization, and XInclude is still forbidden. XML-literal statement
reification now reaches complete graph construction. Every other `parseType`
value follows the same XML-literal production.

The forward XML scanner now accepts the complete XML 1.0 Unicode name ranges
for element, attribute, and namespace-prefix names. Qualified names still have
strict namespace structure: multiple colons and malformed namespace
declarations fail before graph publication, as does an empty property-element
`rdf:nodeID`. Unicode annotation names cross the same retained owner with exact
Python mapping and wire parity.

XML 1.0 value normalization now also happens in the forward scan. Literal text
and CDATA normalize raw CR and CRLF endings to LF, attribute values normalize
raw XML whitespace to spaces, and numeric character references retain their
referenced characters. The same event stream feeds nested XMLLiteral
serialization, including ElementTree-compatible escaped attribute whitespace.
Forbidden raw XML characters and a literal `]]>` in character data fail before
graph or owner publication.

The XML envelope is now validated before RDF parsing. XML declarations require
the ordered `version`, optional `encoding`, and optional `standalone`
pseudo-attributes; the declaration must agree with the detected UTF-8,
UTF-16LE, or UTF-16BE source. UTF-16 byte-order marks and XML byte signatures
select a bounded two-pass decoder that rejects odd code units and invalid
surrogates before allocation, preserves decoded-codepoint accounting, and
continues to reject UTF-32. Reserved `xml`/`xmlns` namespace bindings and
prefixed namespace undeclarations follow the namespace constraints, while an
explicit correct `xml` binding and default-namespace undeclaration remain
valid. The positive envelope crosses retained publication; malformed forms
publish no graph or owner. Declaration versions are restricted to XML 1.0,
and comments reject both embedded double hyphens and a trailing hyphen before
the closing marker.

Ordinary XML processing instructions now follow the RDF/XML Infoset mapping:
their targets and content are lexically validated, then they produce no RDF
events. Instructions before, inside, and after the document element are
accepted, including an inert `xml-stylesheet` target, without invoking a target
handler or external resource. Case-insensitive reserved `xml` targets,
malformed target boundaries, and misplaced XML declarations still fail before
graph publication. Differential and retained-owner fixtures preserve exact
Python mapping and wire parity.

Property-element `rdf:ID` now emits the original statement plus the complete
four-triple RDF 1.1 reification for literal, resource, nested-node,
`parseType="Resource"`, empty and nonempty collection, and XML-literal forms.
The reification IRI follows the active XML base. `rdf:ID` and `rdf:nodeID`
values enforce the XML NCName grammar, including Unicode names, and the
document-wide (`rdf:ID` value, base) uniqueness constraint spans node and
property elements. The ID ledger, object copies, and duplicate checks remain
under native memory/work limits, while every emitted statement remains under
`max_triples`. Classic `rdf:Statement` metadata is still unconsumed by the
strict OWL reverse mapper, so a reified graph fails before retained-owner
publication and makes no capability claim.

RDF/XML 1.1 `parseTypeOther` values now behave exactly like
`rdf:parseType="Literal"` in both the Python reference parser and native forward
scanner. Arbitrary values, nested markup, mixed tails, suppressed inherited
language, XML-literal limits, and optional `rdf:ID` reification reuse the same
bounded event/serialization path without emitting value-specific triples. A
fully mappable annotation fixture crosses the private retained V2 owner with
exact Python canonical, fingerprint, report, wire, and zero-structural-copy
parity.

The private single-document RDF/XML seam now owns anonymous-individual
canonicalization as well. Provisional parser labels are alpha-canonicalized in
Rust against the complete mapped document, assigned exact raw document scopes,
then re-scoped into the ordinal-zero snapshot scope before the typed V2 owner is
frozen. Raw and effective root tables remain distinct, provenance keeps both
origin tables, and Python receives neither structural rows nor a model to
re-scope. Symmetric blank graphs remain bounded by the shared canonical-work
limit. Its parsed trees, labels, paths, graph candidates, and raw/effective
encodings use fallible reservations charged before allocation to both the
temporary-workspace ceiling and the operation-wide live-memory budget. This
does not cover multi-document import scoping or advertise RDF/XML.

The guarded single-document Functional seam now uses that same native scoping
engine instead of exporting complete parser framing for Python re-scoping.
Parser-order raw/effective digest pairs keep duplicate lexical occurrences,
source spans, source maps, and provenance exact even when the canonical root
tables sort and deduplicate the corresponding values. The typed owner retains
distinct raw and effective root/origin tables, while document, structural,
logical, signature, and wire evidence match the Python reference without
invoking the complete Functional model decoder. Scoping allocations remain
under the shared temporary-workspace and live-memory budgets.

The retained publication adapter now accepts a complete ordered set of mapped
documents, one corresponding raw/effective root pair per document, explicit
per-document reachability, and the closure document order. All documents cross
one typed arena, preserving raw per-document rows while deriving effective
document and closure views from retained references. Four-document diamond and
two-document legal-cycle fixtures preserve distinct anonymous identities,
deduplicate closure rows, and report zero structural rows or bytes copied at
publication. A mismatched effective-document table fails as a typed protocol
error before publication. This establishes the native multi-document handoff
and retained topology contract. The public forced-native path now invokes it
for resolver-built Functional diamonds and cycles in either provenance mode,
with exact manifest/fingerprint/wire parity, exact raw/effective/closure origin
views, and real multi-source anonymous scope assignment. Resolver discovery,
complete document models, and canonical row tuple construction remain
Python-owned; end-to-end native shared-import parsing, partial failure, and
bounded parallel orchestration remain open.

Explicit RDF/XML `rdf:nodeID` spellings now survive canonical blank-node
identity as nonsemantic source-map root details. Python and the private native
retained path publish the same sorted `blank-label`, `blank-label:2`, and
subsequent lexical-detail rows for each original structural occurrence.
Generated implicit blank nodes publish no source label, and labels inside an
XML literal remain markup rather than parser metadata. Generated parser
identities use a NUL-prefixed internal domain, which cannot overlap a legal XML
NCName; explicit labels such as `node-1` and `generated-1` therefore cannot
impersonate generated identities. This source evidence remains private,
unadvertised, and absent when source-map retention is disabled.

The private retained RDF/XML seam now also honors explicit partial RDF mapping.
The strict default still rejects every incomplete graph before publication.
When partial mapping is selected, native mapping retains only the first
`max_diagnostics` unconsumed triples in Python graph order, using a
temporary-budgeted bounded heap rather than a proportional evidence copy.
Both the consumed-count pass and the complete evidence-selection scan charge
canonical work and poll cancellation, including consumed prefixes. Literal
evidence uses the active CPython runtime's exact `repr` after detached mapping;
only the already truncated evidence set crosses that bounded conversion and
the final text remains Rust-owned. The retained owner publishes exact lazy
report header, triple, and `OWL2-RDF-REVERSE` rule rows with attested digest,
retained-byte, maximum-row, and page counters. Tests cover strict rejection,
parse/publication option mismatch, diagnostic truncation, generated blank
identity, Unicode-version skew, allocation failure, and classic
`rdf:Statement` metadata. The seam and its report remain private and
unadvertised.

## Acceptance state

WP16 acceptance remains open. In particular:

- the guarded Functional path now constructs and publishes its retained arena
  without eagerly decoding a complete Python structural model or copying
  proportional canonical/preimage/origin data into Python; single-document
  anonymous-node re-scoping is also native, while diagnostic-budget fallbacks
  and resolver-built closure handoff still use complete-model decode;
- RDF/XML, Turtle, and OWL/XML are not complete native ingestion paths, and the
  full Functional format/option/import matrix has not passed retained
  publication despite AUTO, all-policy empty-closure, ignored-import, and
  no-resolver unresolved-import coverage;
- native closure publication now retains real resolver-built Functional
  diamond/cycle manifests, multi-source anonymous scope derivation, and
  provenance origin views, but Python still owns resolver orchestration,
  complete document models, and proportional canonical structural/origin tuple
  construction; partial failure, resolver-to-owner cancellation, and
  deterministic bounded parallel native assembly remain unproved;
- complete diagnostics/source-position, writer, representative external
  corpus, hostile, fuzz, memory/object, and phase-allocation evidence is
  absent; and
- no ingestion format or encoded schema may be advertised from this checkpoint.

WP16 can close only after each advertised format completes the installed-wheel
forced-native matrix, unsupported selections fail before consumption, fallback
detection remains active, and parser-to-arena plus retained-closure evidence
demonstrates that no RDFLib graph, proportional Python triple/axiom collection,
or eager complete Python model conversion occurs.
