# WP16 — native streaming parsing and structural mapping

Status: implementation checkpoint; narrow Functional retained load now publishes
owner first without eager structural-model decoding, complete acceptance open
Prepared: 2026-07-20
Capability claim: none

## Outcome

WP16 now has a fail-closed retained-owner handoff for one deliberately narrow
public load shape: one Functional Syntax document, native parsing selected
explicitly or by the existing AUTO size/capability policy, ignored imports,
source maps disabled, OWL 2 DL validation disabled, no RDF mapping report, and
no anonymous-node re-scope difference. Provenance may be enabled or disabled;
the latter publishes no origin capability or table.
The Functional parser constructs the typed V2 arena directly from its own
canonical nodes in the same detached native call. An opaque one-use owner is
then finalized with the exact publication attestation and origin rows. The
eligible no-anonymous-node path validates and scans the canonical result bytes
owner first: it derives metadata, fingerprints, root partitions, signature,
logical rows, and provenance occurrence records without constructing a
complete `ParsedOntology`, `OntologyDocument`, ordinary `OntologySnapshot`, or
Python `StructuralNode` root graph. Duplicate roots are deduplicated without
losing origin occurrences. Its encoded structural view and PYOCORE writer
consume the retained columns without scalar model traversal.

This is a checkpoint, not WP16 acceptance. The native call still returns the
complete parser-result framing, and Python scans and retains canonical byte
rows, indexes, fingerprint preimages, and optional lightweight provenance
occurrence records proportional to the document. The no-eager-structural-model
proof applies only to the guarded Functional shape; anonymous-node re-scoping
uses the authoritative complete-model fallback, and the other formats and
closure modes remain outside the path. The bridge is intentionally absent from
the ingestion capability ledger, and the encoded view schema is likewise
unadvertised.

## Acceptance state

WP16 acceptance remains open. In particular:

- the guarded Functional path now constructs and publishes its retained arena
  without eagerly decoding a complete Python structural model, but complete
  parser-result bytes, canonical byte rows/indexes, fingerprint preimages, and
  optional provenance occurrence records still cross or materialize in Python
  proportionally; anonymous-node re-scoping still uses complete-model decode;
- RDF/XML, Turtle, and OWL/XML are not complete native ingestion paths, and the
  full Functional format/option/import matrix has not passed retained
  publication despite the additional AUTO and ignored-import fixture;
- native closure assembly does not yet prove shared-import digest parsing,
  diamonds/cycles, anonymous scopes, partial failure, cancellation, or
  deterministic bounded parallel publication;
- complete diagnostics/source-position, writer, W3C/corpus, hostile, fuzz,
  memory/object, and phase-allocation evidence is absent; and
- no ingestion format or encoded schema may be advertised from this checkpoint.

WP16 can close only after each advertised format completes the installed-wheel
forced-native matrix, unsupported selections fail before consumption, fallback
detection remains active, and parser-to-arena plus retained-closure evidence
demonstrates that no RDFLib graph, proportional Python triple/axiom collection,
or eager complete Python model conversion occurs.
