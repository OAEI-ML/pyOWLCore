# WP16 — native streaming parsing and structural mapping

Status: implementation checkpoint; guarded Functional loads now keep structural
publication bytes native, complete multi-format/closure acceptance open
Prepared: 2026-07-20
Capability claim: none

## Outcome

WP16 now has a fail-closed retained-owner handoff for a deliberately guarded
Functional Syntax shape: one document, native parsing selected explicitly or
by the existing AUTO size/capability policy, source maps and OWL 2 DL
validation disabled, no RDF mapping report, and no anonymous-node re-scope
difference. Imports may be ignored, recorded unresolved when no resolver can
produce a closure member, or use either resolver-backed policy when the native
parser proves the direct-import set is empty before publication. An actual
resolver-backed import selects complete framing before publication. Provenance
may be enabled or disabled; the latter publishes no origin capability or table.
The Functional parser constructs the typed V2 arena directly from its own
canonical nodes in the same detached native call. For eligible loads, Python
receives only compact ontology/import metadata and fixed-size prepared digest
evidence. Canonical root temporaries, structural/logical/signature fingerprint
preimages, and origin-row encoding remain native; no ontology-sized canonical
byte collection or provenance occurrence object is copied into Python. Native
preparation streams one temporary row at a time from the retained arena,
enforces cancellation and temporary/owner memory limits, and finalization
rechecks all six content digests plus cardinality and capability claims.
Duplicate roots remain deduplicated without losing origin occurrences. The
encoded structural view and PYOCORE writer consume retained columns without
scalar model traversal.

This is a checkpoint, not WP16 acceptance. The native call still returns the
complete parser-result framing for explicit fallback cases, including
anonymous-node re-scoping and RECORD_UNRESOLVED loads whose diagnostic metadata
would exceed the retained publication bound. The guarded owner-first proof is
still Functional-only; resolver-backed import closure and the other formats
remain outside the path. The bridge is intentionally absent from the ingestion
capability ledger, and the encoded view schema is likewise unadvertised.

## Acceptance state

WP16 acceptance remains open. In particular:

- the guarded Functional path now constructs and publishes its retained arena
  without eagerly decoding a complete Python structural model or copying
  proportional canonical/preimage/origin data into Python; anonymous-node
  re-scoping and diagnostic-budget fallback still use complete-model decode;
- RDF/XML, Turtle, and OWL/XML are not complete native ingestion paths, and the
  full Functional format/option/import matrix has not passed retained
  publication despite AUTO, all-policy empty-closure, ignored-import, and
  no-resolver unresolved-import coverage;
- native closure assembly does not yet prove shared-import digest parsing,
  diamonds/cycles, anonymous scopes, partial failure, cancellation, or
  deterministic bounded parallel publication;
- complete diagnostics/source-position, writer, W3C/corpus, hostile, fuzz,
  memory/object, and phase-allocation evidence is absent; and
- no ingestion format or encoded schema may be advertised from this checkpoint.

WP16 can close only after each advertised format completes the installed-wheel
forced-native matrix, unsupported selections fail before consumption, fallback
detection remains active, and parser-to-arena plus retained-closure evidence
demonstrates that no RDFLib graph, proportional Python triple/axiom collection,
or eager complete Python model conversion occurs.
