# WP16 — native streaming parsing and structural mapping

Status: implementation checkpoint; narrow Functional retained-load handoff
implemented, complete native ingestion acceptance open
Prepared: 2026-07-20
Capability claim: none

## Outcome

WP16 now has a fail-closed retained-owner handoff for one deliberately narrow
public load shape: one Functional Syntax document, forced native parsing,
ignored imports, provenance enabled, source maps disabled, OWL 2 DL validation
disabled, no RDF mapping report, and no anonymous-node re-scope difference.
The Functional parser constructs the typed V2 arena directly from its own
canonical nodes in the same detached native call. An opaque one-use owner is
then finalized with the exact publication attestation and origin rows. No
Python structural-root collection is sent back through the retention binding,
and duplicate roots are deduplicated without losing origin occurrences. Its
encoded structural view and PYOCORE writer consume the retained columns without
scalar model traversal.

This is a checkpoint, not WP16 acceptance. The native call still returns the
complete parser result framing, which Python decodes into `ParsedOntology`,
`OntologyDocument`, and `OntologySnapshot` objects. Python also derives the
publication metadata, fingerprints, effective-row attestations, and origin
sidecars before finalization. The direct arena construction therefore removes
the second Python-to-Rust structural-row round trip, but it does not yet satisfy
the work package's proportional-object or no-eager-model-reconstruction goal.
The bridge is intentionally absent from the ingestion capability ledger, and
the encoded view schema is likewise unadvertised.

- Anonymous-node re-scoping, imports, source maps, OWL 2 DL validation,

- `INGESTION_FEATURES`, `VIEW_FEATURES`, and
  `CoreCapabilities.encoded_view_schemas` remain empty. The existing
  `parse-functional-v1` foundation capability describes document parsing; it

## Acceptance state

WP16 acceptance remains open. In particular:

- the guarded Functional path now constructs its retained arena directly, but
  still eagerly decodes a complete Python model and builds a proportional
  Python document/snapshot plus publication attestation;
- RDF/XML, Turtle, and OWL/XML are not complete native ingestion paths, and the
  full Functional format/option/import matrix has not passed retained
  publication;
- native closure assembly does not yet prove shared-import digest parsing,
  diamonds/cycles, anonymous scopes, partial failure, cancellation, or
  deterministic bounded parallel publication;
- complete diagnostics/source-position, writer, W3C/corpus, hostile, fuzz,
  memory/object, and phase-allocation evidence is absent; and
- no ingestion format or encoded schema may be advertised from this checkpoint.

WP16 can close only after each advertised format completes the installed-wheel
forced-native matrix, unsupported selections fail before consumption, fallback
detection remains active, and parser-to-arena plus retained-closure evidence
demonstrates that no RDFLib graph, proportional Python triple/axiom collection,
or eager complete Python model conversion occurs.
