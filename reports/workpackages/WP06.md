# WP06 handoff report

## Scope completed

WP06 delivers the stable Java-free PYOCORE v1 worker/cache handoff required by
`WP06-wire-cache.md`:

- the frozen `schemas/wire-v1.toml` ledger, generated-runtime constants/checker,
  exact 96-byte header, 72-byte directory, 14 required sections, explicitly
  namespaced optional SWRL section, CRC32C, section SHA-256, and whole-file
  SHA-256 rules;
- deterministic canonical model/document/import/view/origin/footer tables with
  u32 references, u64 bounds/counts, sorted unique rows/postings, safe metadata,
  and no pickle, Python hash/address, native pointer/layout, path credential, or
  Java/runtime-native dependency;
- public `encode_snapshot`, `decode_snapshot`, `open_snapshot`, and
  `write_snapshot` APIs, plus `MappedOntologySnapshot`, `DurabilityPolicy`, and
  a content-addressed `WireCache` facade;
- self-contained overlay/composite encoding through explicit materialization,
  retaining effective structure, origin data, structural context, and the three
  canonical view fingerprints without serializing edit trees or consumer IR;
- bounds-first streaming decode, cancellation/deadline checkpoints, typed
  wire/version/limit failures, deterministic encode-decode-encode, forward
  minor/unknown-optional handling, and unknown-required/schema rejection;
- read-only mmap ownership with metadata-only open, syntax/tag/reference scans
  without model-object retention, single retryable lazy materialization,
  process-local post-fork locks/index caches, atomic-replace stability,
  in-place-change detection, context management, and dependent leases used by
  overlays/composites;
- restrictive same-directory temporary files, independent completed-file
  framing validation, fsync policies, atomic replace, kernel-released advisory
  locks carrying PID/start/token metadata, structural+wire digest cache paths,
  corruption quarantine, symlink/root containment checks, mapping leases, and
  bounded GC; and
- a separate dependency-free reader/re-encoder in `tools/wire_reference`, a
  second package-internal publication oracle that shares no production codec
  helpers, and a frozen empty-v1 byte digest fixture.

The in-process contract remains zero-copy: `coerce_snapshot(existing_view)`
still returns the same view and no wire operation is invoked. Wire is used only
when a caller explicitly requests file/byte/process handoff.

One reproducible pure-Python synthetic measurement used CPython 3.10.11 on the
shared development host, 5,000 declarations, a 133,934-byte Functional-Style

seconds, and mmap-open peak `tracemalloc` allocation was 50,139 bytes. The
decoded snapshot re-encoded byte-identically. This is a bounded synthetic smoke
measurement, not a portable throughput claim; pinned biomedical RSS/distribution
baselines remain WP10.

## Deviations and blockers

- Rust reader/encoder cross-product testing belongs to dependent WP07; v1's
  ledger, independent Python oracle, and public facade are frozen for that
  implementation.
- AFL/libFuzzer/native panic lanes belong to WP07/WP09. WP06 supplies systematic
  Python mutation/truncation coverage and pure-Python ordinary tests.
- Pinned real biomedical corpus regression distributions and platform RSS gates
  remain WP10. The current synthetic meets the specified mmap startup/allocation
  smoke thresholds.

No remaining blocker prevents WP07 or consumer IPC work from consuming wire v1.

## Handoff

Consumers should pass an existing `OntologyView` directly inside one process.
For worker/process boundaries they should call `encode_snapshot`/`decode_snapshot`
or publish once and use `open_snapshot(..., mmap=True)`. Consumer-specific
reasoner/projector/matcher IR remains outside this schema and should be cached by
the core model fingerprint plus the consumer's own compiler schema.
