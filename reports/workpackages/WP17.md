# WP17 — encoded views, wire/mmap, and consumer handoff

Status: implementation checkpoint; candidate schema frozen and exercised,
capability promotion and release evidence open
Prepared: 2026-07-19
Capability claim: none

## Outcome

WP17 now has a generated, versioned structural-column contract and a public
`EncodedStructuralView` implementation for every structural constructor. The
same descriptor and independent decoder cover the complete Python producer,
retained native columns, mapped wire storage, and segmented overlay/composite
views. Direct retained and mmap-backed publications keep their immutable owner
alive and expose read-only buffers without scalar axiom traversal.

The candidate is deliberately unadvertised. The version decision remains
`frozen-unadvertised`, package/API/adapter/wire versions are unchanged, and
`CoreCapabilities.encoded_view_schemas` stays empty. Local source-tree tests and
one clean isolated CPython 3.12 macOS native wheel prove the contract and its
fail-closed boundaries, including a real retained pyELK owner fixture and a
direct/decoded/mmap/overlay/composite installed matrix. They are not the
complete every-format, supported-platform, sanitizer/fuzz, approved-corpus,
performance, and coordinated consumer-release evidence needed to promote the
schema.

## Frozen contract

- Schema name `pyowl-core/structural-columns`, version 1, has generated
  descriptor SHA-256
  `9ad29db6a7e616f65cea2957bc5ba8d1f9b99ef0eb1fe1432c09be25786267b5`.
- The descriptor binds all eleven read-only little-endian buffers, roots,
  canonical ordering and uniqueness, dense-ID scope, segment roles, resource
  limits, fingerprints, and exact owner lifetime.
- A pre-advertisement amendment retained version 1 while adding an explicit
  sorted anonymous-scope mapping for segmented composites. This prevents
  current-scope identities from leaking across base/member/delta boundaries.
- Direct native registration is exact-schema based. Missing operations,
  descriptor drift, malformed metadata, misalignment, invalid references,
  unsupported tags, or limit violations fail before publication.
- Untrusted buffers are validated and copied before publication. Registered
  retained-native columns and validated immutable mappings are the separately
  tested no-base-copy paths.
- Dense IDs are local to the exact view and may not be persisted in consumer
  caches. PYOCORE remains the stable cross-process representation.

## Acceptance state

WP17 acceptance remains open. The repository-owned schema, fallback producer,
retained direct columns, mapped columns, segmented ownership rules, independent
decoder, and public handoff fixtures are implemented, but promotion requires
all of the following to be recorded from clean coordinated revisions:

- an installed-wheel forced-native matrix spanning direct, mmap, overlay, and
  composite owners, hostile/negative cases, and the WP16 format/option matrix;
- a public native operation in each required consumer path with fallback
  disabled, exact identity/result parity, and complete zero-forbidden-work
  counter evidence;
- installed and supported-platform lifetime, corruption, remaining allocation-
  failure, sanitizer/fuzz, alignment/endianness, and hosted close/fork/
  concurrency evidence;
- representative corpus and repair-composite memory/copy/performance evidence;
  and
- a refreshed compatibility manifest with exact final core and consumer
  revisions, supported ranges, artifact identities, and passing release gates.

Until those gates pass, schema 1 remains a frozen candidate only. No package may
infer support from package version or private extension symbols, and the core
must not advertise `pyowl-core/structural-columns` in public capabilities.
