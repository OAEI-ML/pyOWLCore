# WP05 handoff report

## Scope completed

WP05 delivers the reusable immutable asserted-structure views and snapshot-local
cache described by `WP05-indexes-views.md`.

The built-in surface now includes:

- `SignatureView`, with typed punning, declaration-only/reference selection,
  annotation-only selection, exact built-in filtering, kind filtering,
  `entities_by_iri`, and explicit flat-IRI projection;
- `AxiomTypeIndex`, with exact generated constructor postings, generated closed
  declaration/logical/annotation categories, counts, origins, and canonical
  bounded iteration;
- exhaustive `EntityReferenceIndex` postings for typed entities, IRIs, and
  anonymous individuals, using model-tag/field-ordinal paths and an exhaustive
  structural role ledger rather than Python attribute strings;
- `DeclarationIndex` and `AnnotationAssertionIndex`, including undeclared
  referenced entities, subject/property and reverse-IRI lookup, nested
  annotations, and deterministic RFC 4647 basic language preference matching;
- strictly asserted class/property hierarchy views with explicit
  `PRESERVE`/`BIDIRECTIONAL`/`COMPONENT` equivalence handling, separate inverse
  and property-chain records, named endpoint diagnostics, and no reachability,
  inference, transitive reduction, or chain flattening;
- `PropertyDomainRangeView`, retaining every complex value and returning a
  counted result for named-only filtering; and
- `ExpressionOccurrenceIndex`, which interns canonical class/data/property
  expressions per view and retains every container, stable path, role, and
  origin.

`OntologySnapshot.view`, `OntologyOverlay.view`, and `OntologyComposite.view`
now route explicit structural-view requests through one owner-local cache.
Snapshots fully build demanded indexes. Closure overlays retain the base index
and add delta postings/tombstones; root/document overlay requests delegate
unchanged through a base adapter. Composites retain member indexes, anonymous
scope adapters, and bridge postings, and continue to reject root/document
scope. No overlay or composition forces materialization, parsing, resolving,
wire encoding, or a full merged origin index.

The cache provides immutable typed options, canonical request keys, one
publisher per key, unrelated-key concurrency, cooperative cancellation,
retryable failure, re-entry rejection, pre-growth row/byte reservation,
table-level accounting, tighter `max_memory_bytes`/`max_index_bytes` handling,
and shared-row enforcement. A weak identity registry preserves equal-request
identity while a caller holds a view; a bounded strong LRU controls cache-owned
retention. Cache-hit/eviction/failure/wait telemetry is separate from each
view's immutable full/patched/merged build report.

## Concrete contract resolutions

- Cache policy is configured explicitly with `configure_index_cache`; loading
  remains lazy and `LoadOptions` has no prebuild field. `clear_index_cache`
  drops strong retention but deliberately keeps live weak identities.
- `cancellation_token` and `cache_policy` are build controls excluded from the
  semantic options key. Unknown semantic options fail.
- Stable field IDs are `(model constructor tag, zero-based field ordinal)`;
  collection positions are separate path-step indices. Scalar fields are
  terminal ledger entries and never become reference occurrences.
- `AxiomCategory` is the preferred runtime category token; the three existing
  closed PEP 604 category unions are accepted for compatibility.
- Built-in filtering uses an exact typed OWL/RDF/RDFS/XSD ledger. “Implicit”
  means built-ins present in canonical structure, including explicit canonical
  fillers for unqualified restrictions; the view does not inject every
  vocabulary item into every ontology.
- Language selection uses caller preference order and case-folded RFC 4647
  basic prefix matching, canonical structural tie order, then optional untagged
  fallback. Wildcards are intentionally not accepted in this checkpoint.
- PRESERVE exposes asserted equivalence sets without edges; BIDIRECTIONAL adds
  pairwise named edges from each asserted n-ary axiom; COMPONENT joins
  overlapping asserted sets and rewrites named asserted edges to immutable
  component nodes. Optional `DisjointUnion` handling adds only each named
  member-to-defined-class structural edge.
- Accounted bytes are deterministic reservation estimates by posting table,
  not recursive `sys.getsizeof` claims. Shared rows/bytes are reported
  separately from wrapper-owned allocation. Later index timing is kept out of
  frozen `LoadReport` and exposed through `ViewBuildReport`/`IndexCacheReport`.

## Verification evidence

Completed locally on 2026-07-17:

- CPython 3.10.11 and 3.12.3 pass the complete suite with 203 tests and 402
  generated subtests; the WP05 slice contributes 28 tests;
- generated field-role coverage includes every registered constructor field,
  and every structural field is exercised by the every-constructor fixtures;
- scan/materialization parity passes for all nine indexes over both overlays
  and source/target/bridge composites, including paths, roles, origins, complex
  values, expressions, hierarchy edges, declarations, and annotations;
- exact tag/category, typed punning, exact built-ins, annotation/source-origin
  options, root/document/closure, hierarchy counterexamples, chain separation,
  named-filter counts, expression interning, nested annotations, language
  preferences, and hash-seed determinism pass;
- concurrent same-key publication, distinct-key concurrency, pre/mid-build
  cancellation, failure/retry, dependency re-entry, row/byte limits, shared-row
  delta limits, weak identity across LRU eviction, and cache telemetry pass;
- a 250-declaration resident-base matrix proves every built-in overlay build is
  `PATCHED` with at most 1 KiB wrapper-owned accounting and every two-member
  composition is `MERGED` with at most 1 KiB wrapper-owned accounting; and
- static boundary tests and repository audits find no consumer-private IR,
  Java bridge, runtime dependency, or reverse consumer import under
  `pyowl_core.index`.

One reproducible pure-Python biomedical-shaped synthetic measurement on the
shared x86_64 development host used CPython 3.10.11, 1,000 classes, 999 asserted
subclass axioms, 200 labels, and object-property domain/range records (2,202
effective axioms; 60,393 source bytes). Building all nine demanded indexes took
16.626 seconds wall time and 4.01 MiB peak `tracemalloc` allocation; deterministic
table accounting retained 2.82 MiB. Six hundred warm exact-reference,
asserted-parent, and exact-type count queries took 0.312 seconds. A one-axiom
reference overlay built as `PATCHED` in 0.00084 seconds with 602 accounted own
bytes. Outputs were checked before timing. This is WP05 algorithm/accounting
evidence on a controlled synthetic, not a portable throughput claim; pinned
real biomedical corpora, distributions, RSS, and regression baselines remain
WP10.

## Deferred work

`EncodedView` remains omitted. The checkpoint did not produce evidence that a
new public buffer schema would outperform the complete scalar fallback enough
to justify its schema, owner lifetime, and cross-backend obligations. WP08/WP10
may add the provisional form only with Python/native parity and a measured
consumer boundary benefit.

Native index construction/parity belongs to WP08. Real corpus performance and
release thresholds belong to WP10. Wire persistence, mmap lifecycle, and
cross-process cache keys remain WP06 and were not started. The inherited WP02
NCIT RDF-list/individual ambiguity and WP12 setuptools license warning are
unchanged.

## Handoff

Consumers may now request any built-in through the same `OntologyView` identity
received from `coerce_snapshot`. Equal requests reuse identity and work across
snapshots, repair overlays, and OAEI composites without reparsing or private
IR exchange. Consumer compilers should retain their own inferred/normalized IR
and key it by the appropriate core fingerprint plus their compiler schema; no
reasoner, projector, matcher, repair, or evaluator state belongs in these core
indexes.
