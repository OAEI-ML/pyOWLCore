# WP15 — retained native arena and lazy Python facade

Status: implementation checkpoint; million-unique native/Python facade bound
and exact-commit local native safety/lifecycle slices proved, remaining hosted

Prepared: 2026-07-21
Capability claim: none

## Outcome

WP15 has a checked retained Rust arena, an opaque owning publication handle,
and an implementation of the lazy Python document/snapshot surface. The
original `NativeSnapshotPublicationV1` remains the immutable arena/freeze
foundation. Contract testing found that V1 could not satisfy WP15's lazy-facade
acceptance criteria because it exposed counts and ownership but no bounded,
typed scalar query protocol.

`NativeSnapshotPublicationV2` is therefore an explicit versioned amendment,
not a positional extension of V1. It adds a generated semantic ledger,
attestation, bounded page/contains requests, cardinality summaries, auxiliary
row codecs, exact owner roles, and native/Python counters. Its private facade
materializes model and report values on demand, retains the exact owner, and
uses a bounded process-local LRU instead of an ontology-sized permanent Python
cache.

Commit `43e4785` restores continuous native safety lanes and records a clean,
exact-revision local checkpoint. AddressSanitizer and ThreadSanitizer each pass
all 211 production Rust library tests, the dependency-free Miri ownership
harness passes all 13 tests, and the Functional and wire targets each complete
10,000 AddressSanitizer-backed libFuzzer runs without a finding. This closes a
concrete missing harness/buildability gap; it does not stand in for the full
interpreter, platform, format, or scheduled campaign matrices.

Commits `b91bb91` and `0bc75d4` add an actual interpreter-policy lifecycle
matrix and a reproducible subinterpreter probe. The dispatcher now recognizes
Python 3.14's public `concurrent.interpreters` identities before the legacy
private API, so an unsupported subinterpreter cannot be mistaken for the main
interpreter and proceed to extension import. A clean CPython 3.12 test-hook run
passes owner close/GC, teardown, real fork reset, signal, cancellation, GIL,
panic, and thread cases; CPython 3.11 creates, exercises, and destroys eight
subinterpreters through the complete Python fallback without attempting a
native import.

Commit `e7abee8` adds deterministic allocation-failure injection at the actual
PyO3 retained-component boundary. The suite discovers the allocation count for
each of the 76 generated model constructors, injects a failure at every build,
freeze, and encode checkpoint, then proves the first non-failing boundary still
round-trips exact canonical bytes. The exact local sweep covers 20,673
checkpoints: 4,460 during construction, 16,137 during canonical freeze, and 76
during encoding. Build failures poison later mutation and freeze, freeze
failures publish no owner, and encode failures leave the immutable arena
recoverable.

Commit `8799246` advances the private extension ABI to version 2 after the
retained Functional entry point gained its final import-policy argument. The
Python probe now rejects an ABI-1 artifact at metadata validation before
calling native self-test or operation code, so a stale developer artifact
cannot be selected and fail later with an untyped PyO3 arity error. A clean
detached ABI-2 artifact passed 71 focused Python tests plus 157 constructor
subtests, all 220 production Rust tests, rustfmt, strict Mypy, Ruff, and
all-feature Clippy with warnings denied.

Commit `ce8cbba` also restores the semantic-reference boundary around
`PythonParser`. Backend orchestration now lives above the Python parser, so a
direct semantic-reference parse cannot probe, import, or dispatch into the
native extension even when its input options request the native backend. At
detached revision `c8f18e7`, the complete suite passed 1,139 tests plus 3,546
subtests with seven explicit environment/platform skips against the exact ABI-2
artifact. This is clean-tree regression evidence for the parser and extension
boundaries, not completion of the WP15 platform or lifecycle matrix.

Commit `360e82d` closes the previously missing million-unique Python-boundary
proof. A test-hook-only Rust generator constructs one million canonically
ordered, distinct `Declaration(Class(IRI(...)))` rows without a proportional
Python row or model collection, retains them behind the exact registered
`_NativeSnapshotHandle`, and binds only bounded V2 publication metadata in
Python. The public lazy snapshot then traverses all one million scalar axioms
in order while discarding each result. Before access it has zero model
materializations and 21 publication objects; after the complete traversal its
LRU retains 256 entries/183,960 bytes and Python GC sees only 1,637 additional
tracked objects, not an ontology-sized duplicate.

This checkpoint does not advertise `retained-native-load-v1`, a syntax format,
or the encoded structural view. The million-unique generator and the
Python-backed publication constructor remain test hooks. Separately, the WP16
Functional checkpoint now uses the typed Rust construction/freeze seam and
retains the real component arena without a proportional Python collection;
the million fixture deliberately isolates the V2 owner/facade object and cache
contract rather than claiming parser or format coverage.

## Frozen amendment

- `schemas/native-snapshot-publication-v2.toml` is generated from the exact
  typed semantic tree. Its canonical digest binds the envelope, attestation,
  page and contains records, cardinality records, owner members, row codecs,
  ordering, duplicate policy, counters, resource bounds, and capability rules.
- V2 requires named construction and exact public/private record types. Any
  semantic, lifetime, ordering, or field change requires V3.
- Structural rows are canonical-model-v1 bytes. Effective structural and
  origin collections are canonical ascending and unique. Raw source-map and
  raw document-origin collections preserve their separately specified producer
  multiplicity/order while supporting digest-group paging.
- Page requests are bounded by rows, bytes, actual maximum retained row size,
  publication `ParseLimits`, scope, document ordinal, signature selection, and
  the optional digest filter. Totals and page boundaries are pinned for a
  traversal and fail closed on drift.
- Snapshot requests observe effective document/closure collections. Document
  owners observe raw document structural collections where the public document
  contract requires them. Source maps remain raw for both owner roles.
- A handle owns its retained storage. Snapshot forks and document handles have
  independent close state while sharing immutable storage. No borrowed pointer
  or buffer is part of the Python handoff.
- Optional source-map, origin, RDF mapping, and OWL 2 DL collections are
  capability/option gated before an owner call. Diagnostic and validation
  sequences preserve producer order and multiplicity.
- Native and Python counters separate retained component/canonical/auxiliary/
  metadata bytes, builder/freeze peaks, page copies, decoded/materialized rows,
  cache state, parser/wire/view calls, and base flattening.

## Acceptance state

WP15 acceptance remains open. The typed production handoff and million-unique
object/cache requirements now have direct evidence. The following are still
release-blocking for this work package rather than deferred implementation
details:

- complete parser/publication/view/wire and process-allocator failure coverage,
  plus the remaining cancellation, panic, close/fork/concurrency,
  interpreter-lifecycle, supported-platform, and hosted continuous matrices
  beyond the passing local native-safety and CPython 3.11/3.12 slices;
- exercise generated/native-arena and mapped/wire owners across every model
  constructor with exact canonical, fingerprint, order, diagnostic, and hash
  parity; and
- freeze the final verification commands/results and exact handoff revisions in
  this report.

Until those gates pass, WP15 makes no retained-load capability claim. WP16 and
WP17 production checkpoints must remain fail-closed and unadvertised until
their own acceptance matrices pass. Neither successor may reach into the
other's module or treat either test-hook publication constructor as a
production native path.
