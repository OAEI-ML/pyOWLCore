# WP02 handoff report

## Scope completed

WP02 delivers the complete pure-Python, one-document OWL path owned by
`WP02-python-formats-documents.md`. The checkpoint is the `main` commit that
contains this report.

Implemented behavior includes:

- single-pass bounded acquisition from regular paths, bytes-like buffers,
  non-seekable `BinaryIO`, and explicit `TextIO`, with caller-owned stream
  retention, exact/normalized SHA-256 provenance, source limits, deadlines,
  and cancellation;
- deterministic format selection with explicit/media/content/extension
  precedence, ambiguous `.owl`/`.rdf` handling, and mismatch warnings;
- pure-Python Functional-Style, OWL/XML, Turtle, and RDF/XML readers covering
  every OWL 2 structural constructor, nested annotations, imports, anonymous
  individuals, large cardinalities, datatype restrictions, property chains,
  keys, and optional Functional-Syntax SWRL values;
- an indexed immutable RDF graph, complete OWL 2 reverse-mapping paths,
  consumed/unconsumed evidence, strict default rejection, explicit partial
  mapping reports, RDF list cycle/shared-tail checks, n-ary mapping, axiom and
  nested annotation reification, and negative assertions;
- deterministic writers for all four syntaxes, canonical blank labels,
  parse-render-parse structural preservation, explicit lossy extension policy,
  incremental caller-owned stream output, and same-directory atomic path
  publication;
- immutable `OntologyID`, `OntologyDocument`, `Fingerprint`, provenance,
  source-map, origin-index, and RDF-mapping-report contracts, including
  canonical document blank-node freeze and metadata-independent document
  fingerprints; and
- the exact public `parse_document` facade, which records direct imports but
  performs no resolver, network, or import open.

The coordinated shared changes are the reviewed root exports/public-API
snapshot, inclusion of the model schema ledger in source distributions, and a
hot-path `ParseLimits.allowed` lookup optimization. No WP03 resolver, import
closure, or snapshot behavior was introduced.

## Deviations and blockers

No standards deviation, expected-failure marker, Java dependency, runtime
dependency, or copied external corpus was introduced.

Release-grade imported W3C test repositories, errata/deviation ledgers,
property fuzzing, parser differential tests, and formal branch/mutation
coverage remain WP09. Native parser parity and acceleration remain WP08; gated
biomedical/adversarial benchmark baselines remain WP10. Publication metadata,
artifact reproducibility, SBOM/signing, and compiler/Java-absent container
evidence remain WP12. The local build emitted setuptools' already-known future
license-metadata deprecation warning; metadata modernization is owned by WP12.

SWRL is an explicit optional extension: Functional Syntax supports it only via
the expert parser control, while standard OWL-only XML/RDF writers reject or
require an explicit lossy policy. RDF SWRL mapping is not advertised as an OWL
2 capability.

## Handoff

WP03 and consumer packages may rely on:

- `parse_document` parsing one source exactly once, never resolving imports,
  and returning an immutable document whose direct imports are canonical;
- all four required `DocumentFormat` readers producing the same WP01
  structural values, with strict RDF completeness by default;
- `OntologyDocument` equality/fingerprint excluding acquisition provenance and
  source layout while including ontology identity, imports, annotations,
  axioms, extensions, and document-scoped anonymous identities;
- `DocumentProvenance`, optional `SourceMap`, `OriginIndex`, and
  `RDFMappingReport` as immutable public communication contracts;
- `render_document`/`write_document` deterministic canonical output and atomic
  path/caller-owned stream behavior; and
- the reviewed names in `tools/audit/public-api-v0.txt`; consumers must not
  import the internal RDF graph or syntax parser classes.

WP03 owns resolver composition, legal import cycles, closure identity,
document conflict handling, snapshots, and final multi-document anonymous
scope separation. It must preserve the one-document parser's no-resolution
invariant and may re-scope parsed anonymous values only through the explicit
canonical document/snapshot process.
