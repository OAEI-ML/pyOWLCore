# WP22 — supported partial RDF diagnostic mode

## Outcome

The curated `LoadOptions` surface now exposes
`allow_partial_rdf_mapping=False`. When explicitly enabled with an explicit
RDF/XML or Turtle format, `parse_document` may return one nonconformant
`OntologyDocument` carrying the WP20 report and exact dropped-statement count.
Strict behavior remains the default.

The option is rejected before source acquisition for autodetection and
non-RDF formats. It is also rejected for snapshot loading/coercion and existing
views. Already parsed nonconformant documents are rejected by the snapshot
loader, parsed-document cache, and direct `OntologySnapshot` construction.
Consequently a diagnostic document cannot enter a snapshot, wire, reasoner, or
conformant-cache route through the public API.

Native V1 load-option bytes remain frozen and fail closed when the new option
is true. V2 has a distinct attestation domain and appends the exact boolean to
its option ledger, so strict and partial native requests cannot share an
attestation digest accidentally. Native strict publication raises from the
retained first-pass report, while native partial publication returns that same
report without a diagnostic reparse.

## Stable conflicts

| Situation | Code |
|---|---|
| partial mode without explicit RDF format | `PARTIAL_RDF_MAPPING_FORMAT_REQUIRED` |
| partial mode with OWL/XML or Functional Syntax | `PARTIAL_RDF_MAPPING_FORMAT_CONFLICT` |
| snapshot, coercion, cache, direct snapshot, or existing-view route | `PARTIAL_RDF_MAPPING_SNAPSHOT_FORBIDDEN` |
